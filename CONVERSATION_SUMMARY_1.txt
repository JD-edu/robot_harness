로컬 LLM 로봇 Harness 개발 대화 정리
=====================================

1. 프로젝트 목표
---------------

로컬 PC에서 동작하는 Qwen3 8B를 로봇 작업 Planner로 사용한다.

LLM이 모터나 관절을 직접 제어하지 않고, 허용된 Robot Skill과 인자만 계획하게 한다.
Harness는 LLM 계획을 검사한 뒤 안전한 Skill만 실행한다.

전체 역할은 다음과 같다.

LLM      : 무엇을 할지 계획한다.
Harness  : 계획과 인자를 검사하고 실행을 통제한다.
Skill    : pick, place, open_cap 같은 단위 작업을 수행한다.
Robot    : 로봇의 상태를 관리한다.
World    : 물체와 환경의 상태를 관리한다.


2. 로컬 LLM 실행 환경
---------------------

현재 사용 중인 서버:

- Runtime: llama.cpp
- 주소: http://127.0.0.1:8080/v1
- 모델 ID: qwen3-8b
- API 형식: OpenAI-compatible Chat Completions

모델 확인 명령:

curl -fsS http://127.0.0.1:8080/v1/models

Stage 2 실제 LLM 실행 명령:

cd /home/robo/robot_harness
python3 -m stage2_llm_harness.main --llm "PET 병을 왼팔로 잡고 오른팔로 뚜껑을 열어"

실제 Qwen3 호출에서 다음 계획과 실행 성공을 확인했다.

1) 왼팔로 pet 집기
2) 왼팔로 pet을 잡은 상태에서 오른팔로 뚜껑 열기
3) SUCCESS: True


3. 단계별 학습 방향
-------------------

Stage 0부터 Stage 2까지는 가능한 한 일반적인 Python 문법을 사용한다.

초기 단계에서 제거하거나 피한 문법:

- ABC
- abstractmethod
- dataclass
- Enum
- 복잡한 타입 힌트
- 별도의 Step 데이터 클래스
- @property

주로 사용하는 문법:

- 일반 class
- __init__
- 함수
- if 조건문
- for 반복문
- 리스트와 딕셔너리
- try/except
- 문자열 상태값

Stage 3 이후에도 반드시 고급 추상화가 필요한 것은 아니다.
코드 중복, 구현 종류, Skill 수 또는 협업 인원이 실제로 증가할 때 필요한 추상화를
조금씩 도입하는 방향으로 결정했다.

-----------------

각 단계가 자기 폴더 안에 별도의 common/skill_api.py를 갖도록 변경했다.

stage0_skill_api/

    main.py

stage1_symbolic_robot/

    test_harness.py

최상위 common/ 폴더는 제거했다.

각 Stage의 common 코드는 의도적으로 중복된다.
이를 통해 앞 단계의 코드를 수정해도 다른 단계가 갑자기 바뀌지 않으며,
학습자는 단계별로 계약과 추상화가 어떻게 변하는지 직접 비교할 수 있다.

Stage 2는 Stage 1의 Symbolic Robot과 Skill을 불러오지 않고 자체 복사본을 사용한다.
Stage 3은 Stage 2 Harness에 실패 피드백과 재계획 기능을 추가하는 확장 단계이다.


5. 단계별 기능
--------------

Stage 0 - Skill API

- 가장 단순한 Skill 계약을 학습한다.
- SaySkill이 메시지를 출력한다.
- 결과는 success=True 또는 False로 표현한다.

실행:

cd /home/robo/robot_harness
python3 -m stage0_skill_api.main


Stage 1 - Symbolic Robot

- 실제 하드웨어 없이 로봇과 물체 상태를 다룬다.
- 왼손과 오른손이 무엇을 들고 있는지 저장한다.
- pet과 cup의 위치 및 PET 뚜껑 상태를 저장한다.
- pick, place, open_cap을 실행한다.

실행:

python3 -m stage1_symbolic_robot.main


Stage 2 - LLM Harness

- Mock Planner 또는 실제 Qwen3가 JSON 계획을 만든다.
- Harness가 Skill 이름, 단계 수, 인자 구조와 인자 값을 검사한다.
- 허용된 계획만 Symbolic Robot에서 실행한다.
- Qwen의 <think>...</think> 및 Markdown으로 감싼 JSON도 처리한다.
- 현재 World의 정확한 객체 ID를 Qwen에 전달한다.

Mock Planner 실행:

python3 -m stage2_llm_harness.main

실제 Qwen3 실행:

python3 -m stage2_llm_harness.main --llm "PET 병을 왼팔로 잡고 오른팔로 뚜껑을 열어"


Stage 3 - 실패 복구와 재계획

- 현재 Robot과 World 상태를 Qwen에 제공한다.
- 잘못된 계획 또는 Skill 실패 이유를 Qwen에 다시 제공한다.
- max_replans 범위 안에서 수정 계획을 요청한다.
- 복구 예산을 모두 사용하면 안전하게 중단한다.

실행:

python3 -m stage3_recovery_harness.main "PET 병을 왼팔로 잡고 오른팔로 뚜껑을 열어"


6. Python 모듈 실행 방법
-----------------------

다음 실제 파일이 있다고 가정한다.

stage0_skill_api/main.py

Python 모듈 경로에서는 / 대신 .을 사용한다.

stage0_skill_api.main

따라서 다음 명령은 stage0_skill_api/main.py를 모듈 방식으로 실행한다.

python3 -m stage0_skill_api.main

각 부분의 의미:

python3           : Python 3 실행 프로그램
-m                : 모듈 이름으로 실행
stage0_skill_api  : 코드 폴더
main              : main.py 파일

프로젝트 루트에서 실행하는 방법:

cd /home/robo/robot_harness
python3 -m stage0_skill_api.main

Stage 0 폴더에서 직접 실행하는 방법:

cd /home/robo/robot_harness/stage0_skill_api
python3 main.py

Stage 0 main.py는 두 실행 방법을 모두 지원하도록 수정했다.


7. ModuleNotFoundError 수정 내용
------------------------------

다음과 같이 Stage 0 폴더 안에서 파일을 직접 실행했을 때 오류가 발생했다.

/usr/bin/python3 /home/robo/robot_harness/stage0_skill_api/main.py

오류:

ModuleNotFoundError: No module named 'stage0_skill_api'

원인은 파일을 직접 실행할 때 Python의 모듈 검색 기준이 stage0_skill_api 폴더가 되기
때문이다. main.py에서 모듈 실행과 직접 실행을 모두 지원하도록 import를 수정했다.

현재 다음 두 명령 모두 정상 동작한다.

/usr/bin/python3 /home/robo/robot_harness/stage0_skill_api/main.py

cd /home/robo/robot_harness
/usr/bin/python3 -m stage0_skill_api.main

9. **kwargs 설명
----------------

**kwargs는 이름이 붙은 여러 입력값을 하나의 딕셔너리로 받는 Python 문법이다.

예제:

def show(**kwargs):
    print(kwargs)

show(name="pet", arm="left")

함수 안의 kwargs 값:

{"name": "pet", "arm": "left"}

정의에서 **kwargs를 사용하면 여러 이름 입력을 딕셔너리로 모은다.

def show(**kwargs):
    pass

호출에서 **args를 사용하면 딕셔너리를 이름이 붙은 입력값으로 펼친다.

args = {
    "arm": "left",
    "object": "pet"
}

skill.execute(ctx, **args)

위 코드는 다음 호출과 같다.

skill.execute(ctx, arm="left", object="pet")

Harness에서 **args가 유용한 이유는 Skill마다 입력 이름과 개수가 다르기 때문이다.

pick      : arm, object
place     : arm, location
open_cap  : holder_arm, worker_arm, object

Stage 0에서는 이해를 쉽게 하기 위해 일반 매개변수를 사용할 수도 있다.
**kwargs와 **args는 여러 Skill을 공통 Harness에서 실행하는 Stage 2에서 본격적으로
사용하는 것이 자연스럽다.

12. 현재 설계 원칙 요약
-----------------------

- LLM은 모터를 직접 제어하지 않는다.
- LLM은 허용된 Skill과 인자만 계획한다.
- Harness가 모든 계획을 실행 전에 검사한다.
- 각 Stage는 학습을 위해 자체 common 코드를 가진다.
- Stage 0~2는 가능한 한 일반 Python 문법을 사용한다.
- 고급 추상화는 실제 반복과 복잡성이 생길 때 점진적으로 도입한다.
- Symbolic Robot에서 검증한 뒤 MuJoCo와 실제 로봇 Backend로 확장한다.
