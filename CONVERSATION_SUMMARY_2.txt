1. __repr__의 의미
------------------

확인한 코드:

def __repr__(self):
    return "SkillResult(success={!r}, message={!r}, data={!r})".format(
        self.success, self.message, self.data
    )

__repr__은 Python 객체를 확인할 때 어떤 문자열로 보여줄지 정하는 특별한 함수다.

__repr__이 없으면 객체를 출력할 때 다음처럼 메모리 주소 중심의 표현이 나올 수 있다.

<common.skill_api.SkillResult object at 0x...>

__repr__을 작성하면 다음처럼 객체 내부 값을 읽기 쉽게 표시할 수 있다.

SkillResult(success=True, message='message printed', data={'text': 'hello'})

현재 코드에서는 print(result)를 실행할 때 __str__이 별도로 없으므로 __repr__의
결과가 사용된다.


2. 문자열의 {!r} 의미
---------------------

다음 문자열에는 값을 넣을 위치가 세 군데 있다.

"SkillResult(success={!r}, message={!r}, data={!r})"

.format()에 전달한 값이 순서대로 각 {!r} 위치에 들어간다.

첫 번째 {!r} : self.success
두 번째 {!r} : self.message
세 번째 {!r} : self.data

!r은 해당 값을 repr() 방식으로 표현하라는 의미다.

일반 문자열 표현:

"{}".format("hello")

결과:

hello

repr 표현:

"{!r}".format("hello")

결과:

'hello'

repr 표현은 문자열에 따옴표가 표시되므로 값의 자료형과 빈 문자열을 확인하기 쉽다.

__repr__은 Harness 실행에 반드시 필요한 기능은 아니다. Stage 0을 더 단순하게
학습하려면 __repr__을 제거하고 다음처럼 속성을 각각 출력해도 된다.

print("Success:", result.success)
print("Message:", result.message)
print("Data:", result.data)


3. MockPlanner의 Mock 의미
-------------------------

Mock은 영어의 "흉내 내는 것", "모조품"이라는 의미에서 온 개발 용어다.

MockPlanner는 실제 llama.cpp와 Qwen3를 호출하지 않고, Qwen3가 반환할 법한 계획을
미리 만들어 반환한다.

실제 Planner의 흐름:

사용자 명령
→ llama.cpp에 HTTP 요청
→ Qwen3 추론
→ JSON 계획 반환

MockPlanner의 흐름:

사용자 명령
→ 미리 정한 JSON 계획 반환

MockPlanner의 장점:

- llama.cpp가 꺼져 있어도 Harness를 시험할 수 있다.
- Qwen 추론을 기다리지 않고 빠르게 실행할 수 있다.
- LLM 문제와 Harness 문제를 분리해 확인할 수 있다.
- 항상 같은 계획으로 반복 테스트할 수 있다.
- 네트워크 오류와 무관하게 Skill을 테스트할 수 있다.

엄밀한 테스트 용어로는 현재 MockPlanner가 미리 정해진 값을 반환하므로 Stub 또는
Fake에 가까운 면도 있다. 교육용 이름으로는 ExamplePlanner 또는 FixedPlanner도
사용할 수 있지만, 현재 프로젝트에서는 실제 LLM을 대신한다는 의미로 MockPlanner를
사용하고 있다.

Mock Planner 실행:

python3 -m stage2_llm_harness.main

실제 Qwen3 Planner 실행:

python3 -m stage2_llm_harness.main --llm "PET 병을 왼팔로 잡고 오른팔로 뚜껑을 열어"

실질적으로 다음과 같은 중첩 위치를 찾게 된다.

7. LLM 메시지의 system과 user 역할
-----------------------------------

확인한 코드:

messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    {
        "role": "user",
        "content": json.dumps(user_data, ensure_ascii=False, indent=2),
    },
]

이 코드는 Qwen3에게 두 개의 메시지를 순서대로 전달한다.

1) system 메시지
2) user 메시지


8. system 프롬프트
------------------

system 프롬프트는 LLM의 역할과 항상 지켜야 하는 규칙을 정한다.

현재 SYSTEM_PROMPT의 주요 규칙:

- 너는 로봇 작업 Planner다.
- 모터를 직접 제어하지 않는다.
- 설명 없이 JSON 리스트만 반환한다.
- 허용된 Skill만 사용한다.
- 정확한 Skill 인자 이름을 사용한다.
- 현재 상태를 기준으로 계획한다.
- 이미 끝난 작업을 반복하지 않는다.
- object 인자에는 World의 정확한 객체 ID를 사용한다.

즉 system 프롬프트는 다음 질문에 답한다.

"LLM은 어떤 역할을 하고, 어떤 규칙을 지켜야 하는가?"


9. user 프롬프트
----------------

user 프롬프트는 이번 요청에서 실제로 처리할 데이터를 전달한다.

user_data의 구조:

user_data = {
    "allowed_skills": skills,
    "current_state": state or {},
    "previous_failure": feedback,
    "user_command": command,
}

각 항목의 의미:

allowed_skills    : 이번에 사용할 수 있는 Skill 목록과 인자
current_state     : 현재 Robot과 World 상태
previous_failure  : 이전 계획 또는 Skill의 실패 이유
user_command      : 사용자가 로봇에게 내린 자연어 명령

즉 user 프롬프트는 다음 질문에 답한다.

"이번에는 어떤 상태에서 어떤 작업을 해야 하는가?"


10. system과 user를 분리하는 이유
---------------------------------

system과 user의 역할은 서로 다르다.

system : 고정된 역할, 규칙, 금지 사항, 출력 형식
user   : 매 요청마다 달라지는 명령, Skill, 상태, 실패 정보

전체 흐름:

system
"너는 로봇 Planner다. 허용된 Skill만 사용하고 JSON만 출력해라."

→ user
"현재 pet은 테이블에 있다. PET 병을 잡고 뚜껑을 열어라."

→ assistant(Qwen3)
[
  {
    "skill": "pick",
    "args": {"arm": "left", "object": "pet"}
  },
  {
    "skill": "open_cap",
    "args": {
      "holder_arm": "left",
      "worker_arm": "right",
      "object": "pet"
    }
  }
]

역할별로 분리하면 다음 장점이 있다.

- 고정 규칙과 매번 달라지는 데이터를 구분할 수 있다.
- 프롬프트를 읽고 수정하기 쉽다.
- OpenAI-compatible API의 표준 메시지 구조를 따른다.
- llama.cpp, Ollama, vLLM 등 다른 서버로 교체하기 쉽다.
- 추후 대화 기록과 실패 피드백을 추가하기 쉽다.


11. json.dumps의 역할
---------------------

user_data는 Python 딕셔너리다. 하지만 LLM 메시지의 content에는 문자열을 넣어야
하므로 json.dumps()로 JSON 문자열로 변환한다.

json.dumps(user_data, ensure_ascii=False, indent=2)

ensure_ascii=False:

한글을 \u... 형태로 바꾸지 않고 읽을 수 있는 한글로 유지한다.

indent=2:

JSON에 두 칸 들여쓰기를 적용하여 사람이 읽기 쉽게 만든다.

예제 결과:

{
  "user_command": "PET 병의 뚜껑을 열어",
  "previous_failure": null
}
